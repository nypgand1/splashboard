# Splashboard product spec

This file is the source of truth for product behavior. Tests and later feature work check against it.

## Scope

- Web dashboard for Taipei Fubon Braves schedule and single-game views.
- UI theme is **Braves Japanese Clean & Modern (日式簡約 Braves 青空藍)**, inspired by the official **Taipei Fubon Braves** visual identity:
  - `--bg`: `#f8fafc` (pure cool light white background)
  - `--navbar-bg`: `rgba(255, 255, 255, 0.9)` with `backdrop-filter: blur(16px)`
  - `--navbar-border`: `#00b4d8` (2px solid cyan bottom border)
  - `--brand`: `#0077b6` (Royal Blue) & `--brand-2`: `#00b4d8` (Braves Cyan)
  - `--thead-bg`: `#f1f5f9` (solid light gray-blue header with 2px `#00b4d8` bottom line)
  - `--thead-text`: `#0f172a` (deep slate header text)
  - `--row-alt`: `#fbfdff` (clean subtle zebra striping)
  - `--row-hover`: `#e0f2fe` (gentle cyan hover highlight)
  - `--card-bg`: `#ffffff` (white card containers with 10px radius & `#e2e8f0` border)
- Tabs: Top radius 10px, active tab filled with `linear-gradient(135deg, #0077b6, #00b4d8)` and pure white text.
- Page chrome is `dmc.AppShell` with `AppShellHeader` (navbar) and `AppShellMain` (pages). Theme tokens apply on the AppShell, not a separate Bootstrap frame. Navbar and main share one card: same width, fused corners. The header is **in document flow** (not `position: sticky` / `fixed`) so it never overlays the game banner or other content. Main padding is content padding only; do not rely on an AppShell header offset. `.app-shell` does not use `overflow: hidden` (that would become the sticky containing block and pin Report chrome inside the card instead of the viewport). Clip the card radius on the header (top) and `.app-main-content` (bottom) instead.
- Icons use `DashIconify` (Tabler). Bootstrap Icons is not loaded. Report page-delete is a DMC control on the paper shell Python renders, not a JS-inserted SVG.
- Tables & Alignment Rules (strictly unified across `dmc.Table` and `dag.AgGrid`):
  - Every header cell and data cell is **center-aligned**, including `Time`, `Player`, `Lineup`, `Lineups`, `Team`, and all numeric / time statistics.
  - Headers display `AS` for data key `AST` and `PT` for data key `PTS` on Box Score team tables, player grids, lineup grids, Report tables, and PDF. The keys stay `AST` and `PTS`. The score matrix has no points header. Team Key Stats `PIP` and `SCP` keep those fields; the third subheader of each group displays `PT`.
  - Header cells and data cells must share the identical alignment for every column.
  - Team summary tables have a 3.5px left indicator bar (Home: `#0077b6`, Away: `#94a3b8`).
  - Player detail tables prefixed with 8px dot (Home: `#00b4d8`, Away: `#94a3b8`).
- Four states for every data view: loading (`dmc.Skeleton`), empty (English copy plus a next step), error (`dmc.Alert`, recoverable, no traceback), success (the table or chart).
- Responsive Layout (RWD):
  - **Mobile (≤ 768px)**: AppShell full bleed (`border-radius: 0; border: none; box-shadow: none;`), main `padding: 12px`, Tabs single-row smooth horizontal scrolling (`overflow-x: auto`).
  - Data tables (`dmc.Table` and `dag.AgGrid`) never clip columns. Box Score quarter and key-stat cards stack to one column below the `lg` breakpoint (~1200px). When a table is wider than its card, the first column stays sticky and the sheet pans horizontally: touch / trackpad native swipe, desktop mouse click-drag. `cursor: grab` / `grabbing` only if `scrollWidth > clientWidth`; tables that fit keep the default cursor. No overflow fade. Scrollbars are hidden (`scrollbar-width: none`). A drag that moved the sheet does not fire the following click (no sort, no score navigation). Do not hide columns to fit.
  - **Tablet (769px ~ 1024px)**: AppShell outer margin `12px`, `border-radius: 12px`.
  - **Desktop (> 1024px)**: AppShell outer margin `24px`, `max-width: 1440px`, `border-radius: 14px`, floating shadow `0 8px 30px rgba(15, 23, 42, 0.15)`.

## Pages

### Home `/`

- Show `dmc.Skeleton` while the selected league and season schedule loads. League, Season, Game Type, and Show each put that same table skeleton into `#home-schedule-list` as soon as the control changes. Last Update and the controls stay. The slot then becomes the new rows, the empty copy, or the error alert. There is no minimum hold. The 30-second reload does not show this skeleton. The first load is still the skeleton alone, with no Last Update and no filters.
- Layout, top to bottom, after the schedule responds: `Last Update` (`#home-last-update`), quiet filters, then the schedule slot. There is no Home hero. The Game page banner stays. `Last Update` is the same dimmed line as Rotation: `dmc.Text` `size="sm"`, `c="dimmed"`, `mb=8`, `className="no-print"`, left aligned. The 8px under that line is the space before the filters. A successful schedule, a filtered empty list, and an empty season use one list `dmc.Paper` (wrapper id `home-schedule-list`, Paper class `home-schedule-list`; `withBorder`, `radius="md"`, `shadow="xs"`). A load error puts the red `dmc.Alert` in that same slot and does not wrap it in the Paper. Not an AG Grid. Not one Paper per game. `dcc.Interval` id `home-interval` and `dcc.Store` id `home-scope-store` reload the selected league and season every 30 seconds, and again when the scope store changes, including when no game is live. `dcc.Store` id `home-filter-store` is in the initial layout and keeps Show, Game Type, league, and the last season id for each league. Show and Game Type do not refetch and do not move the clock. Changing league or season discards the stored Show and Game Type. The next successful schedule for that scope writes the entry selection below. The clock is `Last Update: {UTC+8 datetime}` with microseconds and the offset, stamped when that render is built. It moves on the first success, each successful 30-second reload, and a successful league or season change, including a successful empty season. A failed 30-second reload keeps the clock and the list already on screen. A first-load failure, or a failed league or season change, shows `Last Update: —` until this league and season succeed. Do not keep the previous scope's time. The first load still shows the skeleton, with no Last Update and no filters, then the error or the schedule chrome.
- **Filter controls**, left to right, wrapping on a narrow width: League, Season, Game Type, Show. League is a quiet `dmc.SegmentedControl` (`PLG`, `EASL`). Season is a `dmc.Select` whose options are that league's hardcoded `(label, season id)` rows, newest first. Labels are `2026-27` style. `searchable` is false, `clearable` is false, `allowDeselect` is false, and the width stays 132. The closed control is not a text field. Game Type and Show stay quiet `dmc.SegmentedControl`s without verbose labels.
  - Default league is `PLG`. Default PLG season is `2026-27`. The first time `EASL` is selected, its season is `2026-27`. Each league keeps its own season id in `home-filter-store`.
  - Both leagues list that organization's Synergy fixtures for the selected season. Team names and venues use `nameFullLocal`. A missing team name or venue renders `TBD`.
  - Game Type: Options are distinct `fixtureType` values this season (`Regular`, `Playoff`, `Final`). Hidden when 0–1 distinct types. An empty `fixtureType` is not an option.
  - Status: Chips ordered as `Upcoming` / `Finished` / `All`. The stored pair is the entry selection below.
    - Upcoming = live-play ∪ unplayed (`SCHEDULED`, `IF_NEEDED`, `DRAFT`, `POSTPONED`, unknown/empty).
    - Finished = `FINISHED` / `CONFIRMED`.
    - All = everything, including void.
- **Status badge** on each compact row: badge **color is the bucket**; **label is the raw API `status`** (strip, no rewrite). `IN_PROGRESS` stays `IN_PROGRESS` (not `LIVE`). Empty status shows `UNKNOWN`.
  - Unplayed (`SCHEDULED`, `IF_NEEDED`, `DRAFT`, `POSTPONED`, unknown/empty): cyan (`#e0f2fe` + `#0284c7`).
  - Live-play (`PENDING`, `ABOUT_TO_START`, `WARM_UP`, `ON_PITCH`, `IN_PROGRESS`): coral (`#fee2e2` + `#dc2626`).
  - Finished (`FINISHED`, `CONFIRMED`): gray (`#f1f5f9` + `#475569`).
  - Void (`CANCELLED`, `BYE`, `ABANDONED`): colder gray (`#e2e8f0` + `#334155`).
- **Score** on each compact row uses `format_score_display`:
  - Finished, live-play, and `ABANDONED`: numeric scores render `Away Score : Home Score` (e.g. `88 : 79`); missing scores render `@`. Never fabricate `- : -`.
  - Unplayed and void: display `@` (Away @ Home convention).
- Compact row scan (list, not a mini-hero; same skeleton at 375px and 1280px):
  - Score line: Away team (`16px`, `fw=800`, right, ellipsis), Score / `@` (`22px`, `fw=900`, `#0077b6`), Home team (`16px`, `fw=800`, left, ellipsis). No status badge on this line.
  - Score well: two `min-width: 3ch` slots with `font-variant-numeric: tabular-nums`; away score right-aligned, home score left-aligned, colon centered. `@` uses the same well (3ch spacers either side of `@`). Never shrink the well to fit names. Never fixed `w=68` on the well or `w=140` on team names. Team names `flex: 1; min-width: 0`. Above 768px, single-line ellipsis and no wrap. At `max-width: 768px`, a CJK name, a name with no Latin letter, or a Latin name of 12 characters or fewer stays one line. A longer Latin name splits, and only line 1 ellipsizes. Three words whose first two, including the space, fit in 12 characters put those two on line 1 and the last word on line 2 (`Goyang Sono` / `Skygunners`, `Hong Kong` / `Eastern`, `Taipei Fubon` / `Braves`; `Taipei Fubon` is 12). Any other split keeps the last two words on line 2 (`Ryukyu` / `Golden Kings`, `Taoyuan` / `Pauian Pilots`, `Formosa` / `Dreamers`, `Hiroshima` / `Dragonflies`, `Anyang Jung Kwan Jang` / `Red Boosters`). The full-name line stays in the DOM at both widths. At `max-width: 768px` it leaves the layout (`display: none`, `visibility: hidden`, `position: absolute`, width 0, height 0, `overflow: hidden`). Above 768px that line is the single-line ellipsis and the split lines stay hidden. The score well never shrinks. No abbreviation table. The Game banner uses this same line.
  - Meta cluster under the score, centered as one nowrap group: `HH:MM | Venue` (a missing venue is `TBD`; omit a missing time; no dangling `|`; ellipsis) glued to the status badge `size="xs"`. The cluster is not `space-between`. Meta text truncates; the badge does not shrink. Date is shown once in the group header `YYYY-MM-DD Day` (e.g. `2026-05-30 Sat`).
- **Sorting**: Upcoming games sort chronologically nearest first (ascending). Finished and All sort newest start first (descending), so a later game on the same day comes first. A missing start time sorts last in every Show.
- **Navigation**: the whole compact row is the hit target. Both leagues are clickable iff `score_is_clickable`: live-play (including `PENDING`), finished, `ABANDONED`. The row is an `html.A` / `dmc.Anchor` to `/game/plg/<fixtureId>` or `/game/easl/<fixtureId>`. Pointer cursor and `--row-hover: #e0f2fe` on clickable rows only. Unplayed and `CANCELLED`/`BYE` are not links (default cursor, no hover). No per-row Dash `n_clicks`. No `ScheduleScoreLink`. Opening a game looks that fixture up inside that league's season table only, default season first. There is no cross-league fallback.
- Filters only change the list. Empty filtered list (season itself is not empty): `No games in this view.` Next step: `Switch Game Type or Show.` Keep Last Update and filters. The copy sits inside the schedule Paper. Do not use the season-empty copy.
- On a failed first load, or a failed league or season change: keep Last Update (`Last Update: —`) and the filters. The list slot is `dmc.Alert` with title `Error` and `Failed to load games. Please try again later.` (HTTP 200, no unhandled exception). It is not inside the schedule Paper. Show stays. Game Type stays hidden because this response has no types. Changing Show or Game Type does not clear the alert and does not refetch. The schedule slot shows that same alert again, so the control skeleton does not stay. A failed fetch does not write `home-filter-store`.
- **Entry selection**. The first load, a league change, a season change, and a full page reload discard the stored Show and Game Type and write the new pair to `home-filter-store`. A 30-second reload does not change either control and does not show the table skeleton. It refreshes the list inside the stored pair. A new `fixtureType` may appear on Game Type; the selection stays. The list may become empty. A failed fetch still does not write the store.
- The entry pair, first match:
  1. A live game: Show `Upcoming`, Game Type the `fixtureType` of the earliest live game.
  2. Otherwise a real unplayed game (`DRAFT`, `SCHEDULED`, `POSTPONED`, unknown/empty, or any other unplayed status except `IF_NEEDED`): Show `Upcoming`, Game Type that earliest game's `fixtureType`.
  3. Otherwise a finished game: Show `Finished`, Game Type the latest finished game's `fixtureType`.
  4. Otherwise Show `Upcoming`. An `IF_NEEDED` game uses that earliest game's `fixtureType` and the list shows those rows. A season with no games uses `No games available.` A season whose games are only void (`CANCELLED`, `BYE`, `ABANDONED`) uses `No games in this view.`
- The selected Game Type is the list filter. The same stage's `IF_NEEDED` rows stay in Upcoming. All is every status of that stage, including void. The chosen type is stored even when Game Type is hidden because the season has 0–1 distinct types. A deciding game with an empty `fixtureType` leaves Game Type unset, and the list is not narrowed by stage. Equal `startTimeLocal` values keep schedule order: earliest is the earlier row, latest is the later row. A missing start time stays out of that comparison unless every candidate is missing one.
- **Show click**, same league and season: keep Game Type when that stage has any row in the new Show. `IF_NEEDED` counts as Upcoming. Otherwise select that Show's default stage and write it. Upcoming's default is the earliest live game, else the earliest real unplayed game, else the earliest `IF_NEEDED` game, and does not return to Finished. Finished's default is the latest finished game. All keeps the stage when that stage has any row. When the new Show has no row of any stage, keep the current Game Type and use `No games in this view.`
- **Game Type click**: Show stays. The list is that stage in the current Show, or `No games in this view.`
- When the season list is empty: keep Last Update (a successful stamp) and the filters. The schedule Paper says `No games available.` Next step: `Check back when the season schedule is published.`

### Game `/game/<league>/<game_id>`

`league` is lowercase `plg` or `easl`. Any other league shows `Failed to load this view. Please try again later.` and does not call the API. `/game/<fixtureId>` is not this route and is not redirected. A missing team name or venue displays `TBD` on Home, the Game banner, and Box Score and Report team columns, for both leagues. Missing means no id, a name-table miss, or a blank name. A missing player name still falls back to the raw id (not `TBD`). Team labels on Rotation, Lineup, Matchups, and Play-By-Play still fall back to the raw id.

Top tabs, left to right, rendered via `dmc.Tabs` with theme chrome (top radius 10px, active tab `linear-gradient(135deg, #0077b6, #00b4d8)` and white text). Tab icons use `DashIconify` (Tabler).

1. Box Score (tab_id: `tab-bs`)
2. Rotation (tab_id: `tab-rotation`)
3. Shot Chart (tab_id: `tab-shot-chart`) — every status and viewport. See Shot Chart.
4. Lineup Stats (tab_id: `tab-lineup`)
5. Matchups (tab_id: `tab-matchups`) — every status and viewport, including 375px. See Matchups.
6. Play-By-Play (tab_id: `tab-pbp`)
7. Report (tab_id: `tab-report`) — **finished games only** (`FINISHED`, `CONFIRMED`) **and desktop** (`viewport >= 1280px`). Every other status, and any viewport under 1280px, hides the Report tab (`display: none`). If Report is active while hidden, switch to Box Score.

Box Score is the default (`value="tab-bs"`). Tab panes stay mounted. Hidden-tab render callbacks gate on `Input('tabs', 'value')`, return `no_update`, and do not rebuild children. Report also returns `no_update` on later Report tab selects while `report-pane-ready` is `1` (empty/error may rebuild).
- Quarter tables (points, fouls, timeouts) and team summary tables (four factors, advanced stats, key stats) are rendered via DMC `dmc.Table` (with `dmc.SimpleGrid` for responsive quarter stats layout).
- Player Stats, Lineup Stats, and Matchups tables use `dag.AgGrid` with `domLayout="autoHeight"` and sortable/filterable columns for interactive exploration.
- Box Score two-team tables (Score, Fouls, Timeouts, Pace & 4 Factors, Key Stats, team box) and the two player sections put the away side above the home side. The key is the fixture's away and home display names, not A→Z. When those names are missing or equal, team-name order is the fallback and the first section keeps the home colors. Score, Fouls, and Timeouts stay side by side on a wide screen and stack Score, Fouls, Timeouts on a narrow screen. Period chips and the 30-second refresh do not change this vertical order. Player sort (`+/-`, PTS, jersey, DNP last) and the pinned TEAM / COACHES and TOTAL stay. Colors follow the team: away dot and stripe `#94a3b8`, home dot `#00b4d8`, home stripe `#0077b6`.
- Latin player labels are shortened from `nameFullLocal` when a cell is painted. CJK names stay full. The stored name stays `nameFullLocal`. The short label is `Initials.Family` with no space after the last initial (`J.Lee`, `K.Y.Lee`). A comma name uses the last word before the first comma as the family and the first word after it as the given name; suffixes `Jr`, `Sr`, `II`, `III`, and `IV` are dropped. If only a suffix follows the comma, the head is parsed as a normal name (`Henry Galinato, Jr.` → `H.Galinato`). When every token is all-caps, the family is the last token (`CJ CANSINO` → `C.Cansino`, `D.J. NEWBILL` → `D.Newbill`). A leading all-caps surname followed by a non-caps token uses that leading run (`TANAKA Makoto` → `M.Tanaka`). A hyphenated given name takes one letter per syllable (`LEE Kai-Yan` → `K.Y.Lee`, `CHEN Fan-Po-Yen` → `F.P.Y.Chen`); a hyphenated family does not (`Rahlir Hollis-Jefferson` → `R.Hollis-Jefferson`). Otherwise the last all-caps token is the family, or the last token when none is all-caps. A particle (`de`, `del`, `van`, `von`, `da`, `di`, `st`, `la`, `le`, `bin`, `al`) stays on the family (`Juan Gomez De Liano` → `J.De Liano`). A dotted initialism is a given name (`D.J Stephens` → `D.Stephens`). A single token stays as written (`Olivia`, `林書豪`). Letters display in title case. The same label is used on Box Score, Report, PDF, Lineup, Matchups, Rotation, Play-By-Play, and Shot Chart. The Player column stays 95px wide. Box Score Player hover shows the full `nameFullLocal` (`_playerFull` on the row; Report and PDF drop columns whose names start with `_`). Clicking Player sorts by family, then initial. Opening order stays `+/-`, then PTS, then jersey. Lineup is not this sort. Team names are not shortened by this rule.
- Report canvas tables are native HTML `<table>` painted in JS from `bs_store` / `lineup_store` (per ADR 0001). Box Score quarter and team summary tables stay `dmc.Table`. No `dbc.Table`, `dbc.Row`, or `dbc.Col` is used anywhere in the codebase. Do not put AG Grid inside Report blocks.
- Box Score quarter and team summary tables use `dmc.TableThead` / `dmc.TableTh` / `dmc.TableTd` (not raw `html.Th`).
- Loading uses `dmc.Skeleton`. Empty copy is `No data available.` Next step: `Open another game from Home.` Error uses `dmc.Alert` with `Failed to load this view. Please try again later.` (no traceback).
- The game banner date is ISO `YYYY-MM-DD`. `game_banner` is a score line, then `date | time | venue` plus badge `size="md"`. The banner status badge uses the same bucket colors and raw `status` label as the Home rows (not `● LIVE`).

A `dcc.Store` that is `None` or invalid JSON is treated as an empty object. Callbacks must not crash.

## Fixture status buckets

Source enum: DataCore `FixturesModel.status` (14 values). Compare after strip. Unknown/empty is **unplayed**.

| Bucket | Statuses | `/live` | Game interval | Report tab | Home score |
|---|---|---|---|---|---|
| Unplayed | `SCHEDULED`, `IF_NEEDED`, `DRAFT`, `POSTPONED`, unknown, empty | no | off | hidden | `@`, not a link |
| Live-play | `PENDING`, `ABOUT_TO_START`, `WARM_UP`, `ON_PITCH`, `IN_PROGRESS` | yes | 30s | hidden | link: `A : H` or `@` |
| Finished | `FINISHED`, `CONFIRMED` | no | off | shown | link: `A : H` or `@` |
| Void | `CANCELLED`, `BYE` | no | off | hidden | `@`, not a link |
| Void (`ABANDONED`) | `ABANDONED` | no | off | hidden | link: `A : H` or `@` |

- Finished games freeze the report cache (no TTL rebuild).
- Live-play games: `/live` routes (except fixture roster and org persons/entities/venues); PBP HTTP cache and live report cache = 25 seconds; Play-By-Play, Rotation, Shot Chart, Lineup Stats, and Matchups share that cadence. Shot Chart keeps its period and player selections across ticks. Lineup Stats rebuilds both team grids while that tab is open and keeps the size control and Show Opp. Matchups rebuilds its rows while that tab is open and keeps the viewpoint, the sort column, and the Lineup filter. Report does not rebuild.
- Unplayed and void games use official routes. The Game page interval stays off. Home still reloads the season list every 30 seconds.

## Background warmup and prefetch

- **Game page Tab warmup**: When a finished game (`FINISHED`, `CONFIRMED`) loads, one background daemon thread precomputes Lineup `(4, 3, 2)` and the Rotation payload into `PostGameReport` memoized caches so tab switching is instantaneous. A load is a `game_id` change, a league change, or the first lineup callback while the interval has not ticked (`n_intervals` still `0`). A later 30-second tick does not start that thread. A game that becomes finished while the page is open does not start it until the next load. The thread is not cancelled when the user leaves. Lineup size 5 still loads on that callback, including live ticks.
- **Font load**: `NotoSansTC-Regular.ttf` (2.2MB) loads when the user exports PDF, not on every Game page render.
- **Home page 2-game prefetch**: On the first Home load and on a league or season change, a background sequential worker prefetches and memoizes `PostGameReport` for up to the two latest finished games in that season. Both leagues use this rule, each with its own token. Latest uses `startTimeLocal`. A missing start time stays out unless every finished game is missing one; those later schedule rows are then the latest. Equal times keep schedule order, and the later row is later. `DRAFT`, other unplayed statuses, live-play, and `ABANDONED` are not prefetched. No finished game means no prefetch. A later 30-second tick does not prefetch. This worker does not precompute lineup or rotation, and it is not cancelled when the user opens a game.

## Rotation

One Plotly object does both jobs: game flow (margin + runs) and simultaneous home/away lineups. Tablet/desktop is the primary canvas. Phone uses the same 3-panel chart (pan on X only). Do not split by team or period on a small screen.

Wrap chrome, top to bottom, all outside the graph Paper:

1. `Last Update` (first child of `#wrap-rotation`).
2. Controls: **Live** chip to the left of the period `dmc.SegmentedControl`, then **Show DNP** (default off).
3. Run chips (in `#pane-rotation` when any run exists). One wrapping row, sorted by start.
4. Graph `dmc.Paper` (`withBorder`, `radius="md"`, `shadow="xs"`, `className="braves-card-wrapper"`, `overflow: hidden`).

Live chip: hidden when the game is not live-play. Filled = follow now; light = unfollowed. Clicking the chart unfollows. Clicking Live reattaches follow and snaps the playhead to now. The live-play 30s interval updates the playhead only while following.

Period chips: `All` plus each period label. `All` shows the full game (`x` from 0 to `game_end`). A period chip zooms the camera to that period's seconds, then the user can pan a fixed-width window across the game. Clamp the window to `[0, game_end]`. After pan, the selected chip follows the period with majority overlap (> 50%); otherwise keep the current chip.

Run chips: `1Q 08:24–05:10  10–2` (same-period labels omit the repeated quarter; light fill; color = side, home blue / away gray). Click always returns the camera to `All` and sets the playhead to the run start. Kills are not chips.

Playhead `T`: not a draggable object. Chart pan moves the camera, not `T`. Any click on the chart sets `T` to that clock time. Other `T` movers are labels only (period start, Run start, Live now). Finished games default `T` to game end. Live-play defaults to follow now.

On-court names stay on the Gantt Y axis (`#7 J.Lee`: jersey, one space, then the short player label). Team names on the figure stay the full name. At `T`, on-court rows get a `●` prefix; bench bars dim. There is no second 5v5 list. Minutes and `+/-` are hover-only.

Run detection: net margin delta ≥ 8, opponent scored ≤ 4 in the interval, wave breaks when the opponent scores 4 consecutive unanswered points. The end is the max-delta instant (not trailing opponent points). The start trims to the first scorer of the tightest qualifying suffix.

Kill detection: three or more consecutive opponent stats possessions that score 0. Trips come from `annotate_possessions` (a shot, free throw, or turnover ends a used trip; an offensive rebound stays in the trip; technical and unsportsmanlike free throws stay outside it). Points on the trip are made field goals and free throws, including an and-one. One made free throw is not a stop. The defending side's own trips are skipped, not a reset. A longer streak is still one kill. Quarters, halves, and timeouts do not reset it. The span runs from the first stop to the last stop. A team with no kill still gets the `3+ STOPS` row.

Chart:

- Shared X (game elapsed seconds) with 3 subplots: away Gantt (`#94a3b8`), margin step-line (`hv`) with dual-color fill (home lead `rgba(0, 119, 182, 0.20)`, away lead `rgba(148, 163, 184, 0.25)`) plus full-height run `vrect` bands and score annotations, home Gantt (`#0077b6`). Each row label is repeated on the right: player names on both Gantt panels (including the on-court `●` prefix and the bench spacer), and the margin chart's numeric ticks on both sides. `margin.l` and `margin.r` are both 112. Vertical rules mark each period start after the first, and one more at `game_end`, all `#94a3b8` width 1. The x-axis stays `[0, game_end]`. On the Rotation tab, viewport width under 768px hides that right lane — player names, the margin numbers, and the right-edge `3+ STOPS` tags — and sets `margin.r` to 24. `margin.l` stays 112. At 768px and above, both lanes stay. The figure still carries the right lane; the tab graph applies the narrow layout in the browser, and applies it again after a later figure update. Report keeps `margin.r` at 112 at every viewport.
- Width 100%. `fig.layout.autosize = True`; do not set `layout.width`. Graph style width `100%`. `config`: `displayModeBar=False`, `responsive=True`, `scrollZoom=False`, `doubleClick=False`. `layout.dragmode='pan'`. X bounded (`minallowed=0`, `maxallowed=game_end`). Y-axes `fixedrange=True`.

### PDF

- Primary: jsPDF walks each paper's DOM (header, table cells, notes, images, rotation plots) and writes **selectable text**, one PDF page per canvas page, portrait A4. Table `th`/`td` whose box sits outside the union of the block's `.grid-stack-item` box and that block's `<table>` layout box (width still the item) are skipped. If that item box is degenerate (width or height under 1mm), do not clip cells to it (paper 297mm crop still applies). Export hydrates one paper at a time, **scrolls that paper into view**, re-hugs tables and rotation on that grid, then pushes overlapping blocks down (does not pack intentional gaps), draws it, then continues; when the run finishes it restores the previous scroll position. Rotation Graph Paper is embedded as PNG via `Plotly.toImage` of the on-screen plot at export (`scale: 2`), not a whole-paper html2canvas. Layout is close to the screen, not pixel-identical. Notes are parsed via a Rich Text DOM Walker:
  - Paragraphs and multi-level lists (`<ul>`, `<ol>`) maintain hierarchical indentation (approx. 5mm per level).
  - List markers are drawn according to hierarchy: Bullet lists render `disc`, `circle`, `square`; Ordered lists render formatted numbers (`1.`, `a.`, `i.`).
  - Formatting spans parse `color` (`<font color="...">` or CSS `color`), highlight background (`style="background-color: ..."` filled via `pdf.rect`), bold/italic font styles, and draw underlines or strikethrough lines.
  - Text segments are automatically word-wrapped. A line is drawn when its top is inside the note box (`cursorY < maxY`). `maxY` is the note box bottom, capped at the paper 297mm. Do not skip a line because less than 40% of a line-height remains. Lines whose top is past `maxY` are not drawn.

PDF maps the paper with separate `scaleX = 210/width` and `scaleY = 297/height`; table text is vertically centered in the cell (`baseline: middle`). Starter `S` is a stroked circle (not the `○` glyph). Captioned-block title dots are filled circles at `.report-block-title-dot`.
- Filename is `{YYYYMMDD}.pdf` from the game date. If the date is missing, `splashboard-report.pdf`.
- Tables keep the on-screen look (striped, bordered, 9px). Stat cells stay `text-nowrap`. Report lineup name cells wrap, and the PDF draws those names on multiple lines instead of ellipsizing them. Do not restyle tables for a separate print theme. Wide tables may clip at the block edge.
- Do not rasterize the whole paper with html2canvas. Browser print is the fallback if the font or jsPDF fails.

## Box Score DNP & Zero-Value Rules

- DNP (Did Not Play) rostered players are included and sorted at the bottom of the bench.
- In AG-Grid, DNP player rows display `DNP` in the `MIN` column with a full-row span (`colSpan`) across subsequent stats columns.
- Numeric statistics with a value of 0 are left blank `''` (including PTS, REB, AST, and shot `M` / `A`). Shot-group `%` (`2FG%`, `3FG%`, `FT%`) stay `''` when attempts are 0 and show `.000` when attempts `> 0` and made is 0. A positive shot-group rate is three decimals with no leading zero (`.833`, `1.000`). `eFG%`, `USG%`, `TOV%`, `ORB%`, and `FT-R` stay one-decimal percents. The shot chart keeps its percent labels. Game AG Grid, Report paper, and PDF share this Python value. Report JS must not treat a `%` string, a leading-dot rate (`.000`), or lineup `PPP` `0.00` as a blank zero.
- `eFG%` is blank when `FGA == 0` (or DNP) and `0.0%` when `(2A+3A) > 0` and `(2M+3M) == 0`.
- `USG%` is blank when unplayed/DNP and `0.0%` when played with 0 usage.
- `+/-` displays pure numbers without `+` prefix (positive in royal blue `#0077b6`, negative in coral red `#e63946`, zero in gray `#64748b`).
